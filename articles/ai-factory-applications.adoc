[abstract]
--
Configuring artificial intelligence (AI) applications in the {kube} environment involves using {helm} charts and custom override files.
While applications ship with default configurations, you can modify application behavior by applying a custom override file with scenario-specific values.
This approach ensures consistent, reproducible and easily manageable application deployment.

This guide provides a list of AI applications installable by {productname}, along with their descriptions and configuration override examples.
--

{ai-app-name} (link:https://www.kubeflow.org[]) is a cloud-native platform that orchestrates and simplifies the entire machine learning (ML) lifecycle on {kube}.
Unlike traditional software with hard-coded rules, ML applications learn to make decisions and predictions directly from data.
{ai-app-name} automates this data-driven process, managing everything from initial development to production deployment.

[#aif-apps-{ai-app-string}]
== {ai-app-name}

{litellm} (link:https://docs.litellm.ai/docs/[]) is an open source large language model (LLM) proxy and abstraction layer.
The service translates diverse provider application programming interfaces (APIs) into a unified, OpenAI-compatible format.
Using {litellm} simplifies multi-model integration so that you can switch between proprietary cloud models and local open source models with minimal code changes.
The proxy also provides centralized key management, detailed usage tracking and rate-limiting across multiple teams.

:ai-app-name: {milvus}
:ai-app-registry: {sappco}

[#aif-apps-{ai-app-string}]
== {ai-app-name}

{milvus} (link:https://milvus.io[]) is an open source, cloud-native vector database designed to store, index and manage massive datasets of high-dimensional vector embeddings.
It accelerates similarity search by separating storage and computing, allowing independent scaling of both layers.
This architecture enables low-latency retrieval across billions of vectors for large-scale artificial intelligence (AI) applications, making it highly effective for retrieval-augmented generation (RAG) and semantic search.
