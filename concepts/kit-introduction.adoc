*Kit* is a command-line AI agent, background daemon, and execution environment. When configured for system administration, Kit provides an interactive terminal interface (TUI), non-interactive one-shot execution for automation scripts, and persistent background sessions via a `systemd` user daemon.

Its primary purpose is to provide a structured environment where an LLM can safely access system information, execute commands, or manage files to perform complex tasks that the model cannot do on its own.

[#kit-introduction-how-it-works]
Kit operates as an orchestrator between the administrator, the configured Large Language Model (LLM), and the target system's tools:

. *Startup & Tool Discovery:* When `kit` starts, it loads its configuration (`.kit.yml`, environment variables, and CLI flags), connects to all configured MCP servers (`initialize`), and fetches their available tool schemas (`tools/list`)[cite: 3]. Unless disabled with `--no-core-tools`, Kit also registers its built-in local tools (such as shell execution and file operations).
. *Prompt Construction:* Once the administrator submits a request, Kit sends the prompt, the active system prompt, and the combined tool request/response schemas to the configured LLM.
. *Action Planning:* The LLM evaluates the request and decides which tools to invoke—either requesting direct tool calls or, when Code Mode (`--codemode`) is enabled, generating a JavaScript routine that chains multiple tool calls together.
. *Tool Execution:* Kit executes the requested operations locally or dispatches `tools/call` requests to the MCP server (synchronously or via asynchronous MCP tasks for long-running jobs).
. *Iterative Evaluation Loop:* Kit returns the execution results (command output, system state, log entries, or configuration contents) to the LLM. The LLM analyzes the output and, if further investigation or remediation is needed, issues subsequent tool calls (bounded by `--max-steps`).
. *Final Response:* Once the administrative check or change is complete, the LLM generates a summary of findings and actions taken, which Kit renders back to the administrator (as formatted text in the TUI or structured JSON via `--json`).
