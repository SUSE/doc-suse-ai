This is the {aif-latest-version} release of {productname}, bringing comprehensive AI workload management capabilities to {ranchera}.

== Key improvements and fixes
- Added a default SUSE partner blueprint catalog, controlled by the `partnerBlueprints` {helm} value and enabled by default. Catalogs declared through {helm} are now read-only on the *Settings* page and in the operator API, and are marked `Managed by Helm` link:https://github.com/SUSE/aif/pull/322[#322].
- Added a `Community` blueprint source. Older operators reject blueprints that use `source: Community` link:https://github.com/SUSE/aif/pull/324[#324].
- The {ranchera} `Extensions` page now shows the logo and title of the {productname} extension instead of a `Third-Party` card. The operator installs the extension the same way {ranchera} does, and the logo is served from inside the cluster, so it also loads in air-gapped installations link:https://github.com/SUSE/aif/pull/325[#325].
- Hardened the installation and cleanup of the UI extension. The operator refuses an extension that has the same name as its server release, and the finalizer only deletes a release that its own resource installed link:https://github.com/SUSE/aif/pull/325[#325].
- Fixed workloads stuck in `Degraded` on clusters whose {fleeta} name differs from the {ranchera} cluster ID. The installation wizards now show cluster display names instead of `c-m-...` IDs link:https://github.com/SUSE/aif/pull/330[#330].
- Fixed the verification panel on the *Settings* page hiding the NGC chart access results when no {nvidia} mirror is set link:https://github.com/SUSE/aif/pull/321[#321].
- The weekly {nvidia} AI Enterprise catalog refresh no longer removes applications that lose {nvidia} AI Enterprise support. It only removes their `Supported` label. Each refresh also produces a report of what changed link:https://github.com/SUSE/aif/pull/309[#309], link:https://github.com/SUSE/aif/pull/323[#323].

== Upgrade notes
- *Partner blueprint catalog in air-gapped installations*: The partner catalog is synchronized from GitHub. In air-gapped installations, disable it with `partnerBlueprints.enabled=false` or point it at an internal mirror link:https://github.com/SUSE/aif/pull/322[#322].
- *Duplicate partner catalogs*: If you added a catalog on the *Settings* page that points to the SUSE partner-blueprints repository, remove it after upgrading. Otherwise, two {fleeta} `GitRepo` resources synchronize the same blueprints and conflict link:https://github.com/SUSE/aif/pull/322[#322].
- *Server-side apply for {helm}-declared catalogs*: Keeping catalogs added on the *Settings* page next to catalogs declared in `blueprintCatalogs` requires server-side apply. Releases first installed with {helm} 3 keep using client-side apply until you run one `helm upgrade --server-side=true` link:https://github.com/SUSE/aif/pull/322[#322].
- *`Community` blueprint source*: {saifoperator} 2.3.0 and earlier reject blueprints with the `Community` source. Do not use it until {aif-latest-version} is the minimum operator version in your environment link:https://github.com/SUSE/aif/pull/324[#324].
