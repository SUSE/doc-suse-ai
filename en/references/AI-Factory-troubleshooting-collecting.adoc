[#aif-collect-essential-info]
== Essential information to collect

*Detailed problem description*::
What happened, when did it happen, what were you doing, what is the expected behavior, and what is the actual behavior?

*Steps to reproduce*::
Can you reliably reproduce the issue? If so, list the exact steps.

*Component versions*::
{productname} version, components versions ({rke2a}, {ranchera}).

*Relevant logs*:: 
* `journalctl` output (filtered by service if possible, or full boot logs).
* {kube} pod logs (`kubectl logs`).

*System information*::
* `uname -a`
* `df -h`
* `ip a`
* `/etc/os-release`

*Configuration files*::
Relevant configuration files such as {helm} chart values, ConfigMaps, etc.

*{kube} information*::
Nodes, Services, Deployments, etc.

[#aif-collect-how-to-collect]
== How to collect

*For logs*::
Redirect command output to files (for example, `journalctl -u rke2-server > rke2_logs.txt`).

*For {kube} resources*::
Use `kubectl get <RESOURCE> -o yaml > <RESOURCE_NAME>.yaml` to get detailed YAML definitions.

*For {helm} chart values*::
Redirect `helm get values` output to a file (for example, `helm get values <RELEASE_NAME> -n <NAMESPACE> -a > <RELEASE_NAME>-values.yaml`).

*For system information*::
Collect output of the commands listed above.

*For {rke2a}/{ranchera}*::
Check the https://www.suse.com/support/kb/doc/?id=000020191[The Rancher v2.x Linux log collector script] article to run The Rancher v2.x Linux log collector script.
