[#aif-runai-requirements]
== Prerequisites
* **DNS resolution and {ingress} controller**: The {runaia} Control Plane and cluster URLs must be fully qualified domain names (FQDNs) resolvable via public or private DNS.
IP addresses are not supported.
In a {kube} environment, you must configure a supported {ingress} controller (such as {nginx}) and DNS records pointing to the {ingress} IP address or host name.
For more information about {ingress} controller requirements, see the link:https://run-ai-docs.nvidia.com/self-hosted/getting-started/installation/install-using-helm/cp-system-requirements#kubernetes-ingress-controller[{runaia} Kubernetes Ingress Controller requirements].
* **TLS certificates**: A configured `{certmanager}` instance with a valid certificate authority (CA) or issuer is required.
While {runaia} supports local or custom CAs, using Let's Encrypt with an HTTP-01 or DNS-01 challenge solver simplifies certificate management.
* **{prometheus} Operator**: Custom Resource Definitions (CRDs) and monitoring components provided by the {prometheus} Operator are required for the {runaia} Cluster installation.
You can deploy the link:https://apps.rancher.io/applications/prometheus-operator[{prometheus} Operator from {sappco}] or install the link:https://github.com/prometheus-community/helm-charts[kube-prometheus-stack].
The Control Plane does not require this stack.

[#aif-runai-limitations]
=== Limitations
* Due to the complexity of {runaia}, blueprints currently do not support deploying either the Control Plane or the Cluster.
Deploy them from the menu:SUSE AI Factory[Apps] catalog instead.
* Select the *{helm}* deployment type during the `Target Cluster` step of the deployment wizard.
Do not select the default `Fleet Bundle` deployment due to an link:https://github.com/rancher/fleet/issues/5630[existing bug in {fleeta}].

[#aif-runai-ingress-dns]
=== Configure DNS resolution for {ingress}

To allow external access to the {runaia} control plane, you must route your FQDNs to the {kube} cluster's {ingress} controller.
{rke2a} deploys the {nginx} {ingress} Controller by default.
For detailed information on supported {ingress} controllers, see the link:https://run-ai-docs.nvidia.com/self-hosted/getting-started/installation/install-using-helm/cp-system-requirements#kubernetes-ingress-controller[{runaia} Kubernetes Ingress Controller requirements].

. Retrieve the external IP address or host name of the {ingress} controller service.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl get service -n kube-system rke2-ingress-nginx-controller
----

. In your DNS provider's management console, create a DNS record (A or CNAME) pointing your FQDN (for example, `runai-control-plane.exampleclouddev.com`) to the retrieved IP address or host name.

[#aif-runai-certmanager]
=== Install {certmanager} (optional)

If {certmanager} is not yet installed, install it from {sappco} using the following steps:

. Create a manifest file named `cert-manager-deployment.yaml` with the following content.
Adjust the credentials to match your environment.
+
[source,yaml]
----
---
apiVersion: v1
kind: Namespace
metadata:
  name: cert-manager
---
apiVersion: v1
data:
  .dockerconfigjson: "<YOUR_ENCODED_APPCO_CREDENTIAL_HERE>"
kind: Secret
metadata:
  name: application-collection
  namespace: cert-manager
type: kubernetes.io/dockerconfigjson
---
apiVersion: v1
data:
  .dockerconfigjson: "<YOUR_ENCODED_APPCO_CREDENTIAL_HERE>"
kind: Secret
metadata:
  name: application-collection
  namespace: kube-system
type: kubernetes.io/dockerconfigjson
---
apiVersion: helm.cattle.io/v1
kind: HelmChart
metadata:
  name: cert-manager
  namespace: kube-system
spec:
  chart: oci://dp.apps.rancher.io/charts/cert-manager
  version: "1.20.0"
  targetNamespace: cert-manager
  dockerRegistrySecret:
    name: application-collection
  valuesContent: |-
    global:
      imagePullSecrets:
        - application-collection
    crds:
      enabled: true
----

. Apply the manifest file to install {certmanager}.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl apply -f cert-manager-deployment.yaml
----

[#aif-runai-clusterissuer]
=== Create a ClusterIssuer
Create a ClusterIssuer to issue TLS certificates for the {runaia} endpoints.
The following example configures Let's Encrypt using an HTTP-01 challenge solver with {nginx} {ingress}.

. Create a manifest file named `cluster-issuer.yaml` with the following content.
Adjust the `email` field to match your email address.
+
[source,yaml]
----
---
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: suse-ai-cluster-issuer
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: "tux@example.com"
    privateKeySecretRef:
      name: suse-ai-letsencrypt-key
    solvers:
    - http01:
        ingress:
          ingressClassName: nginx
----
+
[NOTE]
====
Alternatively, you can use a DNS-01 challenge solver (for example, with Cloudflare or AWS Route 53) by supplying your DNS provider credentials, or use an internal enterprise Certificate Authority.
====

. Apply the manifest file to create the ClusterIssuer.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl apply -f cluster-issuer.yaml
----

[#aif-runai-control-plane]
== Install {runaia} Control Plane
Determine a unique fully qualified domain name (FQDN) from your domain for the {runaia} Control Plane UI and API endpoint.
For example, if your domain is `exampleclouddev.com`, use an FQDN such as `runai-control-plane.exampleclouddev.com`.

[IMPORTANT]
====
Because the {runaia} {helm} chart hardcodes the service URLs, both the {helm} release name and the namespace for the {runaia} Control Plane must be `runai-backend`.
====

[#aif-runai-control-plane-certificate]
=== Create the Control Plane endpoint certificate
. Create a manifest file named `runai-control-plane-endpoint-cert.yaml` with the following content.
Replace the `commonName` and `dnsNames` fields with your own {runaia} endpoint URL.
+
[source,yaml]
----
---
apiVersion: v1
kind: Namespace
metadata:
  name: runai-backend
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: runai-tls
  namespace: runai-backend
spec:
  commonName: "runai-control-plane.exampleclouddev.com"
  secretName: runai-tls-cert
  privateKey:
    rotationPolicy: Always
  issuerRef:
    name: suse-ai-cluster-issuer
    kind: ClusterIssuer
  dnsNames:
  - "runai-control-plane.exampleclouddev.com"
----

. Apply the manifest file to create the certificate.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl apply -f runai-control-plane-endpoint-cert.yaml
----

[#aif-runai-runai-reg-creds-secret]
=== Create the `runai-reg-creds` secret
{runaia} images are hosted in the secure `nvcr.io` registry.
Create a secret named `runai-reg-creds` in the `runai-backend` namespace using your {nvidia} AI Enterprise (NVAIE) credentials, such as a service key, to pull images from `nvcr.io`.

[source,sh,subs="+attributes"]
----
{prompt_user}kubectl create secret docker-registry runai-reg-creds \
  --docker-server=nvcr.io \
  --docker-username='$oauthtoken' \
  --docker-password="<SERVICE_KEY>" \
  --namespace=runai-backend
----

[#aif-runai-control-plane-procedure]
=== Install {runaia} Control Plane

. In the left navigation menu, select menu:SUSE AI Factory[Apps].
. Select btn:[NVIDIA AI Library], search for `run:ai`, and select the application tile.
+
[#fig-aif-runai-control-plane]
.{runaia} Control Plane application
image::aif-runai-install1.png[Screenshot showing {nvidia} applications including {runaia} Control Plane,width=100%]
+
. On the `Basic Information` screen, set both the `Instance Name` and `Namespace` fields to `runai-backend`.
. On the `Target Cluster` screen, set the `Deployment Type` to `Helm`. Do not use the default `Fleet Bundle` option.
. On the `Configuration` screen, override the default {helm} values with your custom configuration, for example:
+
[source,yaml]
----
global:
  domain: "runai-control-plane.exampleclouddev.com"
  ingress:
    ingressClass: nginx
    tlsSecretName: runai-tls-cert
tenantsManager:
  config:
    adminUsername: "tux@example.com"
    adminPassword: "<PASSWORD>"
----

. Review the configuration and select btn:[Install].
The installation takes several minutes to complete.
. Once the deployment is complete, open a web browser, navigate to the {runaia} UI endpoint, and log in with the credentials specified in your {helm} values.
For example, navigate to `\https://runai-control-plane.exampleclouddev.com` and log in with the username `tux@example.com` and your configured password.
. On your first login, accept the {nvidia} user agreement and follow the setup wizard to create your first cluster.
. The {runaia} Cluster can be installed on the same {kube} cluster as the Control Plane.
If you choose this option, the Cluster URL is identical to the Control Plane URL.
Copy and save the installation instructions displayed on the screen.
+
[#fig-aif-runai-control-plane-app]
.{runaia} Cluster application
image::aif-runai-nvidia1.png[Screenshot showing a command to install the {runaia} cluster,width=100%]
+
[IMPORTANT]
====
Do not run the installation commands displayed in the wizard.
The {runaia} Cluster must be deployed using {saifactory} instead.
Record the following values from the wizard setup screen:

* Control Plane URL
* Control Plane Client Secret
* Cluster UID
* Cluster URL

Other wizard steps, such as setting up SAML (Security Assertion Markup Language) authentication or creating teams, are optional and can be configured later.
====

[#aif-runai-cluster]
== Install {runaia} Cluster

[#aif-runai-cluster-requirements]
=== Prerequisites

* Before installing the {runaia} Cluster, you must deploy the {runaia} Control Plane (see xref:aif-runai-control-plane-procedure[]) and create your cluster.
* Obtain the following information from the Control Plane:
  - Control Plane URL
  - Control Plane Client Secret
  - Cluster UID
  - Cluster URL

[#aif-runai-create-namespace]
=== Create the `runai` namespace
The {runaia} Cluster must be installed in the `runai` namespace.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl create namespace runai
----

[#aif-runai-cluster-reg-creds-secret]
=== Create the `runai-reg-creds` secret
{runaia} images are hosted in the secure `nvcr.io` registry.
Create the `runai-reg-creds` secret in the `runai` namespace using your NVAIE credentials (such as a service key) to pull the images.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl create secret docker-registry runai-reg-creds \
  --docker-server=nvcr.io \
  --docker-username='$oauthtoken' \
  --docker-password="<SERVICE_KEY>" \
  --namespace=runai
----

[#aif-runai-install-prometheus]
=== Install {prometheus} Operator
The {runaia} Cluster requires Custom Resource Definitions (CRDs) and monitoring components provided by the {prometheus} Operator.
You can install the link:https://apps.rancher.io/applications/prometheus-operator[{prometheus} Operator from {sappco}] or deploy the {prometheus} community stack via {helm}.

. Create a file named `prometheus-operator.yaml` with the following content.
+
[source,yaml]
----
---
apiVersion: v1
kind: Namespace
metadata:
  name: monitoring
---
apiVersion: helm.cattle.io/v1
kind: HelmChart
metadata:
  name: prometheus
  namespace: kube-system
spec:
  repo: https://prometheus-community.github.io/helm-charts
  chart: kube-prometheus-stack
  version: "87.19.1"
  targetNamespace: monitoring
  valuesContent: |-
    grafana:
      enabled: false
----

. Apply the manifest file to install the {prometheus} stack.
+
[source,sh,subs="+attributes"]
----
{prompt_user}kubectl apply -f prometheus-operator.yaml
----

[#aif-runai-install-cluster]
=== Install {runaia} cluster
. In the left navigation menu, select menu:SUSE AI Factory[Apps].
. Select btn:[NVIDIA AI Library], search for `run:ai`, and select the `Run:ai (self-hosted) Cluster` application tile.
. On the `Basic Information` screen, set the `Namespace` field to `runai-backend`.
You can leave the `Instance Name` field with the default value `runai-cluster`.
. On the `Target Cluster` screen, set the `Deployment Type` to `Helm`. Do not use the default `Fleet Bundle` option.
. On the `Configuration` screen, override the default {helm} values with your custom configuration.
Use the values for `controlPlane.url`, `controlPlane.clientSecret`, `cluster.uid`, and `cluster.url` obtained in the previous step.
+
[source,yaml]
----
controlPlane:
  url: "runai-control-plane.exampleclouddev.com"
  clientSecret: "<SECRET_KEY>"
cluster:
  uid: "b735bbc6-a26e-477e-8e83-5a78156bee00"
  url: "https://runai-control-plane.exampleclouddev.com"
clusterConfig:
  global:
    ingress:
      ingressClass: nginx
----

. Review the configuration and select btn:[Install].

[#aif-runai-verify]
== Verify installation

After the {runaia} Cluster installation is complete, verify that the cluster is connected to the {runaia} Control Plane:

. In a web browser, log in to the {runaia} Control Plane UI.
. In the left navigation menu, select menu:Resources[Clusters].
. In the *Clusters* table, verify that your cluster is listed and its status is displayed as *Connected*.
+
For more information about cluster status indicators and cluster management, see the link:https://run-ai-docs.nvidia.com/self-hosted/infrastructure-setup/procedures/clusters#clusters-table[{runaia} Clusters documentation].
