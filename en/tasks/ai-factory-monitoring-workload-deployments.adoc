[#aif-monitoring-workload-deployments-intro]
== Introduction

Each deployment initiated from {ailibrary} or a custom blueprint creates an `AIWorkload` custom resource (`ai-platform.suse.com/v1alpha1`).
The operator tracks the lifecycle of the workload across target clusters and updates its status.

The `AIWorkload` resource specification defines how the application or blueprint is deployed:

* `spec.deployStrategy`: The orchestrator deployment method, which can be `FleetBundle`, `Helm` or `GitOps`.
* `spec.fleetBundleNames`: The list of {rancherfleet} `Bundle` custom resource names managed for this workload.
  Workloads sourced from an application have one bundle entry.
  Workloads sourced from a blueprint have one bundle entry per component.
* `spec.targetClusters`: The list of target {ranchera} cluster IDs (such as `local` or downstream cluster identifiers).
* `spec.targetNamespace`: The target namespace where workload pods and services run.

You can query the `AIWorkload` custom resource to determine the deployment strategy and target resources, then query the underlying orchestrator resources to monitor deployment progress or troubleshoot failures.

[#aif-monitoring-workload-deployments-prerequisites]
== Prerequisites

* An operational {rke2a} {kube} cluster with {productname} installed.
* Administrative access using the `kubectl` command-line utility.
* For {helm}-deployed workloads, the `{helm}` CLI installed locally.

[#pro-aif-monitoring-workload-deployments]
== Procedure

. Query the `AIWorkload` custom resources across all namespaces to view general deployment status:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get aiworkloads -A

NAMESPACE   NAME                 DISPLAY NAME                    STRATEGY      PHASE     AGE
rag         nvidia-rag-minimal   NVIDIA RAG (minimal, low-GPU)   FleetBundle   Running   6d23h
----
+
The output displays the namespace, name, user-friendly display name, deployment strategy (`STRATEGY`), current phase (`PHASE`) and age of each workload.

. Inspect the details of the `AIWorkload` custom resource in its namespace:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl describe aiworkload -n <NAMESPACE> <WORKLOAD_NAME>
----
+
For example, for a workload named `nvidia-rag-minimal` in namespace `rag`:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl describe aiworkload -n rag nvidia-rag-minimal

Name:         nvidia-rag-minimal
Namespace:    rag
Labels:       <none>
Annotations:  <none>
API Version:  ai-factory.suse.com/v1alpha1
Kind:         AIWorkload
Metadata:
  Creation Timestamp:  2026-06-18T13:18:05Z
  Finalizers:
    ai-factory.suse.com/cleanup
  Generation:          2
  Resource Version:    21912
  UID:                 11f009b9-5ded-4dc7-91e3-b469eb9b3cf7

  Deploy Strategy:  FleetBundle

    nvidia-rag-minimal-k8s-nim-operator

    Blueprint:
      Name:         nvidia-rag-minimal
      Version:      2.5.0
    Source Type:    Blueprint
  Target Clusters:
    local
  Target Namespace:  rag
Status:
  Cluster Statuses:
    Cluster Id:  local
    Phase:       Running
  Observed Generation:  2
  Phase:                Running
Events:                 <none>
----
+
[TIP]
====
To view the raw YAML definition instead, run:
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get aiworkload -n <NAMESPACE> <WORKLOAD_NAME> -o yaml
----
====
+
Review the `Deploy Strategy` field to determine the next monitoring step:
+
* If `Deploy Strategy` is `FleetBundle`, proceed to xref:pro-aif-monitoring-workload-deployments-fleet[].
* If `Deploy Strategy` is `Helm`, proceed to xref:pro-aif-monitoring-workload-deployments-helm[].
* If `Deploy Strategy` is `GitOps`, proceed to xref:pro-aif-monitoring-workload-deployments-gitops[].

[#pro-aif-monitoring-workload-deployments-fleet]
== Monitor workloads deployed with the `FleetBundle` strategy
. List all {fleeta} bundles across namespaces to observe their deployment state:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get bundles -A

NAMESPACE     NAME                                      BUNDLEDEPLOYMENTS-READY   STATUS
fleet-local   aif-operator                              1/1
fleet-local   fleet-agent-local                         1/1
fleet-local   nvidia-rag-minimal-k8s-nim-operator       1/1
fleet-local   nvidia-rag-minimal-nvidia-blueprint-rag   0/1                       Modified(1) [Cluster fleet-local/local]; ...
----
+
Each bundle corresponds to an entry from `spec.fleetBundleNames`.
The `BUNDLEDEPLOYMENTS-READY` column indicates how many target clusters have successfully applied the bundle.
The `STATUS` column reports errors or drift, such as `Modified`, `WaitApplied` or `ErrApplied`.
. Inspect the bundle details, status conditions and deployment events:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl describe bundle -n fleet-local <BUNDLE_NAME>
----
+
For example:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl describe bundle -n fleet-local nvidia-rag-minimal-k8s-nim-operator

Name:         nvidia-rag-minimal-k8s-nim-operator
Namespace:    fleet-local
Labels:       fleet.cattle.io/fleet-helm-name=nvidia-rag-minimal-k8s-nim-operator
Annotations:  <none>
API Version:  fleet.cattle.io/v1alpha1
Kind:         Bundle
Metadata:
  Creation Timestamp:  2026-06-18T13:18:06Z
  Finalizers:
    fleet.cattle.io/bundle-finalizer
  Generation:  1
Spec:
  Default Namespace:  rag
  Helm:
    Chart:                k8s-nim-operator
    Disable Pre Process:  true
    Release Name:         nvidia-rag-minimal-k8s-nim-operator
    Repo:                 https://helm.ngc.nvidia.com/nvidia
    Version:              3.1.1
  Targets:
    Cluster Name:  local
Status:
  Conditions:
    Last Update Time:  2026-06-18T13:18:33Z
    Status:            True
    Type:              Ready
  Display:
    Ready Clusters:  1/1
  Summary:
    Desired Ready:  1
    Ready:          1
Events:             <none>
----
+
Examine the `Status.Conditions`, `Status.Summary` and `Status.Display` fields for readiness status, replica counts and failure messages.
. Query `BundleDeployment` resources on the {fleeta} management cluster to inspect per-cluster deployment progress:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get bundledeployments -A
----

[#pro-aif-monitoring-workload-deployments-helm]
== Monitor workloads deployed with the `{helm}` strategy
. Configure `kubectl` and {helm} to use the kubeconfig context for a target cluster listed in `spec.targetClusters`.
Repeat the following checks for each target cluster.
. List active {helm} releases in the target namespace specified in `spec.targetNamespace`:
+
[source,console,subs="+attributes"]
----
{prompt_user}helm list -n <TARGET_NAMESPACE>
----
. Check the deployment status and revision history of the {helm} release:
+
[source,console,subs="+attributes"]
----
{prompt_user}helm status <RELEASE_NAME> -n <TARGET_NAMESPACE>
{prompt_user}helm history <RELEASE_NAME> -n <TARGET_NAMESPACE>
----
. Check the readiness of pods belonging to the {helm} release in the target namespace:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get pods -n <TARGET_NAMESPACE>
----
+
If any pod is in a `Pending`, `CrashLoopBackOff` or `ImagePullBackOff` state, inspect its events:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl describe pod <POD_NAME> -n <TARGET_NAMESPACE>
----

[#pro-aif-monitoring-workload-deployments-gitops]
== Monitor workloads deployed with the `GitOps` strategy
. Verify that the {fleeta} `GitRepo` custom resource successfully clones and watches the repository:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get gitrepos -A
----
. Inspect the detailed synchronization status of the `GitRepo`:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get gitrepo <GITREPO_NAME> -n <GITREPO_NAMESPACE> -o yaml
----
. Once the repository synchronizes, {fleeta} creates the corresponding bundles.
Monitor the generated bundles as described in xref:pro-aif-monitoring-workload-deployments-fleet[]:
+
[source,console,subs="+attributes"]
----
{prompt_user}kubectl get bundles -A
----
