[#aif-app-workloads-manage]
== How do I manage application workloads?
. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Manage] button for the application workload you want to manage.
. In the `Manage` wizard, you can update the application version, destination cluster and 
{helm} chart details.
. Confirm with btn:[Save].

[#aif-app-workloads-upgrade]
== How do I upgrade application workloads?
. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Manage] button for the application workload you want to upgrade.
. On the `Basic Information` screen, change the target version number.
. Finish the wizard and the workload upgrade starts automatically.
+

[#aif-bp-workloads-manage]
== How do I customize blueprint workloads?

You can change the {helm} values of the components of a running blueprint workload and include or exclude individual components.

. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Manage] button for the blueprint workload you want to customize.
The instance name, namespace, target cluster and deployment type cannot be changed.
. On the `Configuration` screen, edit the values of the components you want to change.
To remove a component from the workload, clear its btn:[Include] check box.
At least one component must remain included.
+
[WARNING]
====
Excluding a component that is already deployed removes its resources from the cluster on the next synchronization.
====
. On the `Review` screen, verify the changes and confirm with btn:[Save].

{productname} saves only the values that differ from the blueprint defaults.
When the configuration of a workload differs from its blueprint, either by changed values or by excluded components, the `Workloads` page shows a `Customized` badge next to the blueprint source.

[#aif-bp-workloads-upgrade]
== How do I upgrade blueprint workloads?
. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Upgrade] button for the blueprint workload you want to upgrade.
Once the rollout completes, the workload returns to the `Running` state at the new version.
+

[#aif-bp-workloads-rollback]
== How do I roll back a blueprint workload?

If an upgrade does not complete successfully, you can return the workload to the previous blueprint version.

. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Roll Back] button for the blueprint workload you want to revert.
. Review the target version in the confirmation dialog and confirm the rollback.

[NOTE]
.Rollback target
====
A blueprint version becomes a rollback target only after it has been fully rolled out across every target cluster of the workload.
A workload that has never reached this state has no rollback target, and the btn:[Roll Back] button is not available.
====

[#aif-bp-workloads-retry]
== How do I retry a failed deployment?

If a deployment fails for a transient reason, such as a registry that was temporarily unreachable, you can repeat it without changing the blueprint version.

. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Retry] button for the failed blueprint workload.

[NOTE]
.Supported workload types
====
The btn:[Upgrade], btn:[Roll Back] and btn:[Retry] operations apply to blueprint workloads only.
Application workloads reject these operations.
To change an application workload, use btn:[Manage] as described in xref:aif-app-workloads-manage[].
====

[#aif-workloads-status]
== How do I inspect the status of a workload?

A workload that is not in the `Running` state reports its status for each component and each pod, including while a deployment is still in progress or failing.
Use this detail to identify the component that is blocking the rollout before you retry or roll back.

. From the main left panel, select menu:SUSE AI Factory[Workloads]. You will see the underlying pod status in the status column in the table.
. To see the details of a workload, select its name.
A details panel opens and shows the following information:
** the source of the workload, its deployment strategy, target namespace and target clusters
** the blueprint description and components, or the application chart
** the status and messages for each target cluster
** the {helm} values of each component, with the workload overrides merged onto the blueprint defaults
** the names of the underlying {fleeta} resources or {helm} release
+
To change the workload, select btn:[Manage] in the details panel.
. To inspect the underlying resources in {ranchera}, select btn:[Open in Rancher] for the workload.
For an application workload, this opens the {helm} release; for a blueprint workload, it opens the namespace.
For a workload that targets multiple clusters, select the cluster first.

[NOTE]
.Status of application workloads deployed with {helm}
====
The status of an application workload deployed with {helm} is derived from the readiness of its pods:

* `Running`: all workloads of the {helm} release are ready.
* `Pending`: the pods are still starting, for example while a container image or an AI model is being downloaded.
The workload remains `Pending` for as long as the startup takes.
* `Degraded`: a pod reports a failure, such as `CrashLoopBackOff`, `ImagePullBackOff` or an unschedulable pod.
The status message contains the reason.

A pod that is stuck for a reason reported only as a pod event, such as a volume that cannot be mounted, remains `Pending`.
If a workload stays `Pending` for an unexpectedly long time, inspect its pods in {ranchera} or with `kubectl describe pod`.
====

[#aif-workloads-delete]
== How do I delete workloads?
. From the main left panel, select menu:SUSE AI Factory[Workloads].
. Select the btn:[Delete] button for the workload you want to uninstall, and confirm the deletion.

[NOTE]
.Deleting workloads outside the UI
====
Deleting an `AIWorkload` resource with `kubectl` or through GitOps uninstalls the underlying {helm} chart only when a {ranchera} API token is configured in the `Rancher API Access` section of menu:SUSE AI Factory[Settings].

Without a token, the deletion is intentionally held rather than leaving the {helm} release behind, and the workload reports that it is waiting for the uninstall.
To complete such a deletion, either configure a token or uninstall the application from the {ranchera} `Apps` page.
====
