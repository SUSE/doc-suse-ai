[IMPORTANT]
====
New releases may include breaking changes that require manual intervention.
Always review the companion `README` file for release-specific instructions before upgrading.
====

To upgrade {productname} on the command line, follow these steps:

. (_Optional_) Identify the operator chart version number that you want to upgrade to, for example:
+
[,sh,subs="+attributes"]
----
{prompt_user}skopeo list-tags docker://{aif-operator-registry}
----
+
The latest version is {aif-latest-version}.

. Save all values of the AIF Operator {helm} chart to `values.yaml` and customize them if required.
Omit `--version` to display the latest chart.
+
[,sh,subs="+attributes"]
----
{prompt_user}helm show values oci://{aif-operator-registry} \
  --version {aif-latest-version} \
  --output yaml \
  > values.yaml
----

. Upgrade {saifoperator}.
Omit `--version` to upgrade to the latest chart.
+
[source,bash,subs="+attributes"]
----
{prompt_user}helm upgrade --install \
  aif-operator oci://{aif-operator-registry} \
  -n aif-operator \
  --version {aif-latest-version} \
  -f values.yaml
----
+
The upgrade can take a few minutes.

[NOTE]
.Custom resource definitions on upgrade
====
CRDs are installed on first installation through the standard `crds/` directory of the chart.
Because {helm} never upgrades that directory, the chart applies CRD schema changes through a pre-install and pre-upgrade job (`crds.manageWithJob=true`).
The job only creates or updates CRDs; it never deletes them.

The job requires the `kubectl` image defined by the `crds.image` values.
In an air-gapped environment, mirror this image or override the registry.

In restricted environments where the installer cannot create cluster-scoped RBAC, set `crds.rbac.create=false`, create the service account, cluster role and cluster role binding in advance, and set `crds.serviceAccountName` to the name of the service account in the release namespace.

To skip the job entirely, set `crds.manageWithJob=false`.
You are then responsible for applying the CRDs from the chart's `crds/` directory with `kubectl apply --server-side -f crds/` before each upgrade.
====

[NOTE]
.{ranchera} readiness check
====
Before the operator is installed or upgraded, a pre-install and pre-upgrade job waits until the required {fleeta} and {ranchera} catalog CRDs and the `cattle-ui-plugin-system` namespace are available.
The job waits for as long as the installer allows, for example as set by `helm --timeout` or by the {fleeta} `helm.timeoutSeconds` option.
If {ranchera} does not become ready within that time, the installation or upgrade fails.

The job uses the `kubectl` image defined by the `global.kubectl.image` values, by default `registry.suse.com/suse/kubectl:1.35`.
In an air-gapped environment, mirror this image or override the registry.
====

[IMPORTANT]
.Changes to review before upgrading to {aif-latest-version}
====
* *Upgrade the operator and the UI extension to matching versions.*
Repository chart-access checks, blueprint customization and partner icons require both the {aif-latest-version} operator and the {aif-latest-version} UI extension.

* *Mirror the new `kubectl` image in air-gapped environments.*
The {ranchera} readiness job uses the image defined by `global.kubectl.image`.

* *New CRD and CRD changes.*
The `blueprintcatalogs.ai-factory.suse.com` CRD is added, and the `AIWorkload`, `Blueprint` and `Settings` CRDs are updated.
The CRD job applies these changes during the upgrade.

* *The status of application workloads deployed with {helm} may change.*
Workloads that previously showed `Running` may show `Pending` or `Degraded` after the upgrade if their pods are not ready.

* *The `aif-ui-config` ConfigMap is retained when the UI extension is uninstalled.*
If you install the UI extension chart on its own, without the operator, over an existing `aif-ui-config` ConfigMap, run `helm install` or `helm upgrade` with the `--take-ownership` option ({helm} 3.15 or newer).

* *Custom repository names are reserved.*
Custom chart repositories cannot use the names of built-in {productname} repositories, default {ranchera} repositories, {nvidia} team repositories or other existing `ClusterRepo` resources.

* *Blueprints with `source: Partner` require {aif-latest-version}.*
Operator version 2.2.0 rejects this value.
If you publish blueprint catalogs, do not use it until {aif-latest-version} is the minimum operator version that you support.
====
