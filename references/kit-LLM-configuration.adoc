Kit decouples agent execution from the underlying language model using a unified `model` format and configurable wire protocols (`openai`, `openai-compat`, `anthropic`, `google`). Administrators can connect Kit to an internal LLM gateway, a local inference server (e.g., Ollama, vLLM), or a cloud provider without altering the agent's operational workflow. 

A simple configuration of a local LLM looks as follows:

[source,yaml]
----
# ~/.kit.yml
model: <PROVIDER_NAME>/<MODEL_ID>
system-prompt: |
  You are a system administration assistant. Always verify system state before 
  making changes, prefer least-invasive operations, and report exact commands 
  and outcomes.
----

You can connect Kit to external LLMs in two ways: using authentication via CLI or through an internal gateway. 
[source,yaml]
----
# ~/.kit.yml
model: <GATEWAY_NAME>/<MODEL_ID>

providers:
  <GATEWAY_NAME>:
    name: "Internal LLM Gateway"
    wire: <WIRE_PROTOCOL>               # openai-compat | openai | anthropic | google
    baseUrl: "https://<LLM_GATEWAY_HOST>/v1"
    apiKeyEnv: ["<LLM_API_KEY_ENV_VAR>"]
    headers:
      X-Environment: "sysadmin"
----




== Environment Variables / CLI Authentication

Credentials stored via `kit auth login` are written to `$XDG_CONFIG_HOME/.kit/credentials.json` (defaults to `~/.config/.kit/credentials.json` with `0600` permissions) and take precedence over environment variables.

Authenticate and store the API key for your provider non-interactively while setting its default model as the system default:
+
[source,bash]
----
kit auth login <PROVIDER_NAME> --api-key "<LLM_API_KEY>" --set-default
----

. Verify that the credentials are registered and active:
+
[source,bash]
----
kit auth status
----

Alternatively, export the model and API key via environment variables in the service or shell profile.

[source,bash]
----
export KIT_MODEL="<PROVIDER_NAME>/<MODEL_ID>"
export KIT_PROVIDER_API_KEY="<LLM_API_KEY>"
----

== Configuring connection through internal LLM gateway

If your organization routes LLM traffic through an internal proxy/gateway or self-hosted server, declare a provider override in `~/.kit.yml`. Set `wire` to match the API protocol spoken by your endpoint (`openai-compat`, `openai`, `anthropic`, or `google`):

[source,yaml]
----
# ~/.kit.yml
model: <GATEWAY_NAME>/<MODEL_ID>

providers:
  <GATEWAY_NAME>:
    name: "Internal LLM Gateway"
    wire: <WIRE_PROTOCOL>               # openai-compat | openai | anthropic | google
    baseUrl: "https://<LLM_GATEWAY_HOST>/v1"
    apiKeyEnv: ["<LLM_API_KEY_ENV_VAR>"]
    headers:
      X-Environment: "sysadmin"
----
