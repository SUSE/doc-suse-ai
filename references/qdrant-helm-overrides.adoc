[#qdrant-chart-example-basic]
.Basic custom values file when the cluster has no default storage class set.
====
[source,yaml,subs="+attributes"]
----
# qdrant_custom_overrides.yaml
global:
  imagePullSecrets:
    - suse-ai-registry
persistence:
  accessModes: ["ReadWriteOnce"]
  size: 10Gi
  annotations: {}
  storageClassName: local-path <.>
  # storageVolumeName: qdrant-storage
  # storageSubPath: ""
  # volumeAttributesClassName: ""

----
<.> Use `local-path` storage only for testing purposes.
For production use, we recommend using a storage solution suitable for persistent storage, such as {sstorage}.

[#qdrant-chart-example-gpu]
.An example where {qdrant} uses GPU capabilities.
====
[source,yaml,subs="+attributes"]
----
# qdrant_custom_overrides.yaml
global:
  imagePullSecrets:
    - suse-ai-registry
env:
  - name: QDRANT__GPU__INDEXING
    value: "1"
  - name: QDRANT__LOG_LEVEL
    value: debug
image:
  registry: dp.apps.rancher.io
  repository: containers/qdrant
  pullPolicy: IfNotPresent
  useUnprivilegedImage: false
  tag: "v1.17.0-gpu-nvidia"
persistence:
  accessModes: ["ReadWriteOnce"]
  size: 10Gi
  annotations: {}
  additionalLabels: {}
  # storageVolumeName: qdrant-storage
  # storageSubPath: ""
  storageClassName: local-path <.>
  # volumeAttributesClassName: ""
resources:
  requests:
    nvidia.com/gpu: 1
  limits:
    nvidia.com/gpu: 1
----
<.> Use `local-path` storage only for testing purposes.
For production use, we recommend using a storage solution suitable for persistent storage, such as {sstorage}.
