== Release {aif-latest-version}

This release builds on the 2.2.x line with customizable blueprint deployments, custom chart repositories and Git-sourced blueprint catalogs, clearer repository and workload health reporting, and a new workload details view, plus several stability and installation improvements.

=== What's new

==== Blueprint customization
- *Customize blueprint deployments*: A new `Configuration` step in the blueprint installation and management wizard lets you override {helm} values and enable or disable individual blueprint components before deployment. Disabled components are left out of the deployment and removed from the cluster. Blueprint workloads can be reconfigured later with the btn:[Manage] action link:https://github.com/SUSE/aif/pull/265[#265].
- *Configuration drift tracking*: Workloads report whether their configuration differs from the blueprint defaults, and the `Workloads` page shows a `Customized` badge next to the blueprint source. Only the values you changed are saved, not the full set of component values link:https://github.com/SUSE/aif/pull/287[#287].
- *Partner icons and `Partner` source*: Blueprints accept an optional `icon`, either an `https://` URL or a base64-encoded raster `data:` URI of up to 16 KB, which is shown next to the source badge, and a new `Partner` source value. Updating a blueprint with an invalid specification now returns HTTP `422` instead of `500` link:https://github.com/SUSE/aif/pull/292[#292].

==== Custom blueprint catalogs
- *Git-sourced blueprint catalogs*: Administrators can add external Git repositories that contain blueprint definitions in the `Custom Catalogs` section of *Settings* or through the `blueprintCatalogs` {helm} value. The operator synchronizes each catalog into the cluster through its own {fleeta} `GitRepo` resource, with its own credential and CA certificate secrets link:https://github.com/SUSE/aif/pull/281[#281].
- *New `BlueprintCatalog` CRD*: A cluster-scoped resource that describes a curated, branded collection of blueprints link:https://github.com/SUSE/aif/pull/281[#281].
- *Browse blueprints by catalog*: The `Blueprints` page provides a catalog filter. Blueprints bundled with the chart are listed under `SUSE Blueprints` link:https://github.com/SUSE/aif/pull/281[#281].

==== Custom chart repositories
- *Manage chart repositories from Settings*: Administrators can add, edit and delete {helm} (HTTP or HTTPS), OCI and Git chart repositories, including credentials, in the `Repositories` section of *Settings*. The operator creates a `ClusterRepo` resource with the same name for each repository, and its applications are listed in the application catalog under their own library link:https://github.com/SUSE/aif/pull/244[#244].
- *Single-chart OCI repositories*: Repositories whose URL already ends with the chart name, for example `oci://ghcr.io/nvidia/openshell/helm-chart`, install correctly with both {helm} and {fleeta}. Use this to add the {nvidia} OpenShell charts link:https://github.com/SUSE/aif/pull/244[#244], link:https://github.com/SUSE/aif/pull/293[#293].
- *Verify before saving*: Custom repositories can be tested for credentials, reachability and access to a sample chart from the same form link:https://github.com/SUSE/aif/pull/244[#244].

==== Repository verification and readiness
- *Three-part connection test*: In *Settings*, btn:[Test] reports the registry connection, access to a sample chart, and the readiness of the {ranchera} chart repository as separate results, so a successful login alone is no longer reported as success. The result names the chart and version that were tested, and denied access, missing content, invalid indexes, TLS errors and timeouts each have their own explanation link:https://github.com/SUSE/aif/pull/242[#242].
- *Repository failures shown across the UI*: The `Overview` page lists failing managed repositories with links to *Settings* and {ranchera}. Applications from an unavailable repository remain visible but cannot be installed, and the installation wizard explains missing repository indexes instead of reporting `configmaps "" not found` link:https://github.com/SUSE/aif/pull/242[#242].
- *Explicit refresh*: btn:[Test] is read-only. A new btn:[Refresh] action asks {ranchera} to download the index of a saved repository again link:https://github.com/SUSE/aif/pull/242[#242].

==== Workload monitoring
- *Workload details*: Selecting a workload name on the `Workloads` page opens a details panel with the source, deployment strategy, target namespace and clusters, blueprint components, per-cluster status messages, value overrides, and the underlying {fleeta} resources or {helm} release link:https://github.com/SUSE/aif/pull/221[#221], link:https://github.com/SUSE/aif/pull/303[#303].
- *Accurate status for {helm} workloads*: Application workloads deployed with {helm} now derive their status from pod and controller readiness. A crash-looping or unschedulable pod reports `Degraded` with the reason, and a pod that is still starting reports `Pending` for as long as it needs. Previously, a workload was reported as `Running` as soon as its {helm} release existed link:https://github.com/SUSE/aif/pull/260[#260].

==== Air-gapped deployments
- *{nvidia} repository aliases preserved in mirror mode*: Switching to a private {nvidia} mirror keeps every repository alias derived from the catalog, such as `nvidia-runai` or `nim-nvidia`, so existing workloads can still be upgraded and redeployed link:https://github.com/SUSE/aif/pull/237[#237].
- *Bundled catalog logos*: Logos for 81 {suseai} charts are bundled with the UI extension, so application tiles show the correct logo in connected and air-gapped installations, including behind private mirrors link:https://github.com/SUSE/aif/pull/245[#245].

==== Application catalog
- *{nvidia} catalog refresh*: The weekly {nvidia} AI Enterprise catalog refreshes are included. NGC applications that lost their {nvidia} AI Enterprise support label, including several NeMo microservices, two NIM embedding models and `dgxc-admission-controller`, remain in the catalog without the `Supported` label. The {nvidia} GPU Operator no longer has the `Supported` label link:https://github.com/SUSE/aif/pull/301[#301].

==== Packaging
- *{ranchera} readiness check*: A pre-install and pre-upgrade hook job waits until the required {fleeta} and {ranchera} catalog CRDs and the `cattle-ui-plugin-system` namespace exist before the operator is installed, and retries on temporary API errors link:https://github.com/SUSE/aif/pull/277[#277], link:https://github.com/SUSE/aif/pull/289[#289].

=== Key fixes
- The UI extension no longer remains in the `Failed` state after the operator re-creates its `aif-ui-config` ConfigMap. The operator now takes {helm} ownership of an existing ConfigMap instead of failing every installation and upgrade with an `invalid ownership metadata` error link:https://github.com/SUSE/aif/pull/218[#218].
- Custom UI extension settings are retained after uninstalling. The `aif-ui-config` ConfigMap was previously deleted with the release, so custom operator connection and catalog settings were lost on reinstallation link:https://github.com/SUSE/aif/pull/218[#218].
- Failing {helm} workloads are no longer reported as `Running`. For example, a NIM pod that did not fit in GPU memory was reported as `Running` while it was crash-looping link:https://github.com/SUSE/aif/pull/260[#260].
- {kubeflow}, {litellm} and {qdrant} no longer fail on the first installation wizard screen when chart access is denied or the {ranchera} repository is disconnected despite a successful registry login link:https://github.com/SUSE/aif/pull/242[#242].
- Applications such as {ollama} show their own logo instead of a generic icon when their metadata contains a logo URL link:https://github.com/SUSE/aif/pull/245[#245].
- Switching to an {nvidia} mirror no longer breaks later upgrades of applications installed from {nvidia} team repositories link:https://github.com/SUSE/aif/pull/237[#237].

=== Upgrade notes
- *Mirror the `kubectl` image for air-gapped installations*: The new {ranchera} readiness hook job uses the `registry.suse.com/suse/kubectl:1.35` image, which you can configure with the `global.kubectl.image` values. The job waits until {ranchera} is ready, limited only by the installer timeout, such as `helm --timeout` or the {fleeta} `helm.timeoutSeconds` value link:https://github.com/SUSE/aif/pull/277[#277], link:https://github.com/SUSE/aif/pull/289[#289].
- *New CRD and settings*: The `blueprintcatalogs.ai-factory.suse.com` CRD and the `blueprintCatalogs` and `customRepos` settings are added, and the `AIWorkload` and `Blueprint` CRDs are updated. The CRD hook job of the chart applies them on upgrade link:https://github.com/SUSE/aif/pull/281[#281], link:https://github.com/SUSE/aif/pull/244[#244], link:https://github.com/SUSE/aif/pull/265[#265].
- *Use matching operator and UI extension versions*: Chart access checks, blueprint customization and partner icons require both the {aif-latest-version} operator and the {aif-latest-version} UI extension link:https://github.com/SUSE/aif/pull/242[#242], link:https://github.com/SUSE/aif/pull/265[#265], link:https://github.com/SUSE/aif/pull/292[#292].
- *{helm} workload status may change*: Application workloads that were previously reported as `Running` may now report `Pending` or `Degraded` if their pods are not ready link:https://github.com/SUSE/aif/pull/260[#260].
- *`aif-ui-config` is retained on uninstall*: Uninstalling the UI extension now leaves the `aif-ui-config` ConfigMap in place. Delete it manually for a clean reinstallation link:https://github.com/SUSE/aif/pull/218[#218].
- *Standalone installations of the UI extension chart*: Installing or upgrading the `aif-ui` chart with `helm` without the operator, over an existing `aif-ui-config` ConfigMap, requires the `--take-ownership` option, available in {helm} 3.15 and later link:https://github.com/SUSE/aif/pull/218[#218].
- *Reserved custom repository names*: Custom repositories cannot use the names of the built-in {productname} repositories, the default {ranchera} repositories, the {nvidia} team repositories, or a name already used by another `ClusterRepo` resource link:https://github.com/SUSE/aif/pull/244[#244].
- *`Partner` blueprint source*: {saifoperator} 2.2.0 rejects blueprints with the `Partner` source. Do not use it until {aif-latest-version} is the minimum operator version in your environment link:https://github.com/SUSE/aif/pull/292[#292].

=== Known issues and limitations
- Air-gap support covers private chart repositories, private Git repositories, repository credentials and CA trust. Preparing the cluster remains a separate task: node and {containerd} registry mirrors, DNS, host proxies and operating system repositories are not configured by {productname}.
- Container image references inside blueprint values are not rewritten. Your {containerd} registry mirrors must resolve them transparently.
- Git over SSH is not supported for blueprint input and GitOps output. Use HTTPS with credentials and, where required, a private CA certificate.
- Blueprint partner icons specified as `https://` URLs do not load in air-gapped installations. Use base64-encoded `data:` URIs instead.
- A custom HTTPS repository that uses a certificate issued by a private CA is not trusted through the CA bundle alone. As a workaround, enable `Skip TLS verification` for that repository.
- Anonymous connection tests against OCI registries that require repository-scoped tokens, such as GitHub Container Registry, report an authentication failure even though the charts can be pulled anonymously.
- Chart access is only checked for `https://` {helm} and `oci://` repositories. A plain `http://` {helm} repository can pass the connection test but reports a configuration error for chart access.
- Running chart access checks repeatedly against repositories with very large indexes can exceed the operator memory limit and restart the operator.
- The OpenShell gateway chart requires the Agent Sandbox CRDs and controller (`agents.x-k8s.io`) on the target cluster.
- A {helm} workload whose pod is stuck for a reason that is only reported as a pod event, such as `FailedMount` for a missing secret or ConfigMap, remains `Pending` instead of `Degraded`.
- Upgrade, rollback and retry apply to blueprint workloads only. A workload that has never reached a healthy, fully rolled out state has no rollback target.

== Release 2.2.0

This release builds on the 2.1.x line with enhanced support for air-gapped deployments, recovery operations for blueprint workloads, an {nvidia} AI Enterprise application catalog that is generated and refreshed automatically, and a range of reliability fixes in the operator's {helm} lifecycle.

=== What's new

==== Application catalog
- *Generated {nvidia} AI Enterprise catalog*: The {nvidia} {ailibrary} is generated from the {nvidia} GPU Cloud (NGC) catalog and gated on {nvidia} AI Enterprise support, replacing the previously hand-maintained label refresh link:https://github.com/SUSE/aif/pull/223[#223].
- *Automated catalog refresh*: A scheduled job regenerates the catalog weekly, so the `Supported` labels on {nvidia} applications stay current between releases link:https://github.com/SUSE/aif/pull/232[#232].
- *NGC repository classification*: NGC repository paths are classified as organization, public, gated or excluded. Gated repositories are provisioned with the authentication secret, and unrecognized paths fall back to anonymous access link:https://github.com/SUSE/aif/pull/223[#223].
- *NGC image pull secret injection*: {nvidia} charts receive the `ngc-secret` image pull secret under both supported chart value conventions, which resolves `403` errors caused by an empty default suppressing the injection link:https://github.com/SUSE/aif/pull/223[#223].
- *Catalog scoped to managed repositories*: The `Apps` page lists applications only from `ClusterRepo` resources that {productname} created. Previously, an unrelated `ClusterRepo` could add applications to the {suseai} or {nvidia} libraries link:https://github.com/SUSE/aif/pull/182[#182].

==== Air-gapped deployments
- *Private chart and Git sources*: Blueprints reference a chart repository by its identity, while the registry endpoints in *Settings* determine where that repository is hosted. The same blueprints therefore deploy unchanged against a local mirror. Private HTTPS Git is supported for both blueprint input and GitOps output link:https://github.com/SUSE/aif/pull/224[#224].
- *Private CA certificate propagation*: You can select a CA certificate secret for {sappco}, {sregistry} and {nvidia} in *Settings*. The operator propagates it to {ranchera} and {fleeta}, and handles CA certificate and credential rotation link:https://github.com/SUSE/aif/pull/200[#200].
- *{nvidia} blueprint repository in mirrored mode*: Both the {nvidia} application and {nvidia} blueprint repository identities are preserved when mirrored and pointed at your private OCI URL, so {nvidia} blueprints continue to resolve link:https://github.com/SUSE/aif/pull/201[#201].
- *Image registry override*: A single `global.imageRegistry` value redirects every image shipped by the operator and UI extension charts link:https://github.com/SUSE/aif/pull/209[#209].

==== Workload recovery
- *Upgrade, roll back and retry*: Blueprint workloads can be upgraded to a new blueprint version, rolled back, or retried after a failed deployment directly from the UI. Application workloads do not support these operations link:https://github.com/SUSE/aif/pull/214[#214].
- *Verified rollback target*: A blueprint version becomes a rollback target only after it has been fully rolled out across all target clusters, so a workload cannot be rolled back to a version that never reached a healthy state link:https://github.com/SUSE/aif/pull/214[#214].
- *Per-component and per-pod status*: Workloads report their status for each component and pod, including while a deployment is failing, which makes it easier to identify the component that is blocking the rollout link:https://github.com/SUSE/aif/pull/214[#214].

==== Usability improvements
- *Open workloads in {ranchera}*: Each workload row provides an btn:[Open in Rancher] action that opens the corresponding {helm} release or namespace, with a cluster selector for multi-cluster workloads link:https://github.com/SUSE/aif/pull/206[#206].
- *Library filter is preserved*: Cancelling an application installation returns you to the library you were browsing, and filtered catalog views can be bookmarked and shared link:https://github.com/SUSE/aif/pull/215[#215].
- *Catalog metadata for the UI extension*: The extension is listed as {saifactory} with the correct metadata in the {ranchera} `Apps` and `Marketplace` views link:https://github.com/SUSE/aif/pull/230[#230].
- *Clearer confirmation dialogs*: The upgrade and rollback confirmation dialogs explain the effect of the operation link:https://github.com/SUSE/aif/pull/229[#229].

==== Packaging
- *CRD lifecycle*: CRDs are installed natively on first installation, and a hook job applies schema upgrades. The new `crds.rbac.create` and `crds.serviceAccountName` values support restricted environments where the installer cannot create cluster-scoped RBAC link:https://github.com/SUSE/aif/pull/202[#202].
- *Per-component {helm} release names*: Blueprint components accept an optional `releaseName` value that pins the {helm} release name of a component. It defaults to the chart name link:https://github.com/SUSE/aif/pull/202[#202].
- *UI extension installed by the operator*: The operator installs the UI extension itself, so `aif-ui` is no longer installed as a separate {helm} chart link:https://github.com/SUSE/aif/pull/233[#233].

=== Key fixes
- Restarting the operator no longer leaves the UI extension's {helm} release in a `failed` state without recovering link:https://github.com/SUSE/aif/pull/199[#199].
- The UI extension no longer remains on an incorrect version after consecutive upgrades and downgrades link:https://github.com/SUSE/aif/pull/177[#177].
- Deleting an application workload now uninstalls the underlying {helm} chart instead of leaving the release in the `Uninstalling` state with orphaned resources link:https://github.com/SUSE/aif/pull/193[#193].
- The operator no longer downloads the UI extension chart on every reconcile, which previously caused continuous registry traffic and could exhaust public registry rate limits link:https://github.com/SUSE/aif/pull/185[#185].
- Attaching image pull secrets no longer removes other service account fields, such as labels, annotations, owner references and finalizers link:https://github.com/SUSE/aif/pull/192[#192].
- Several user interface strings and tooltips that previously displayed raw translation keys now render correctly link:https://github.com/SUSE/aif/pull/211[#211].
- Long {helm} release names no longer prevent the UI extension from installing. The generated service name could exceed the {kube} 63-character limit and be rejected link:https://github.com/SUSE/aif/pull/210[#210].

=== Upgrade notes
- *CRDs are retained on uninstall*: `helm uninstall` no longer removes CRDs or the `Settings` resource. Bundled blueprints and the UI extension are still removed. Schema upgrades are applied by a pre-install and pre-upgrade hook job link:https://github.com/SUSE/aif/pull/202[#202].
- *Mirror the `kubectl` image for air-gapped installations*, because the CRD hook job requires it. Alternatively, set `crds.manageWithJob=false` and apply the CRDs manually with `kubectl apply --server-side -f crds/` before each upgrade link:https://github.com/SUSE/aif/pull/202[#202].
- *The UI extension is no longer installed separately*: If your automation installs the `aif-ui` chart as a separate step, remove that step and the `aiExtension.enabled: false` override link:https://github.com/SUSE/aif/pull/233[#233].
- *Deleting workloads outside the UI requires a {ranchera} token*: Deleting an `AIWorkload` resource with `kubectl` or through GitOps only uninstalls the chart when a token is configured in *Settings > Rancher API Access*. Without a token, the deletion is held rather than orphaning the {helm} release link:https://github.com/SUSE/aif/pull/193[#193].
- *Manually created chart repositories are ignored*: Only `ClusterRepo` resources created by {productname} contribute to the application catalog link:https://github.com/SUSE/aif/pull/182[#182].
- *HTTPS Git authentication*: The authentication type setting is deprecated, and existing configurations continue to work.
For new authenticated HTTPS configurations, select a password or personal access token.
The user name is optional unless the Git server requires an account name.
SSH is not supported link:https://github.com/SUSE/aif/pull/224[#224].
- *Unused settings were removed*: The {sappco} API endpoint, catalog discovery and image rewrite settings, and the *Advanced* section of *Settings* were removed link:https://github.com/SUSE/aif/pull/224[#224].
- *New workload validation*: Review existing `AIWorkload` resources before upgrading. The deployment strategy is now immutable, blueprint workloads require at least one target cluster, and GitOps workloads cannot combine the local cluster with downstream clusters link:https://github.com/SUSE/aif/pull/214[#214].
- *Image overrides for air-gapped installations*: The `global.imageRegistry` and `global.imagePullSecrets` values of the `aif-operator` chart are now forwarded to the managed `aif-ui` chart. Existing nested overrides take precedence link:https://github.com/SUSE/aif/pull/209[#209].

=== Known issues and limitations
- Air-gap support covers private chart repositories, private Git repositories, repository credentials and CA trust. Preparing the cluster remains a separate task: node and {containerd} registry mirrors, DNS, host proxies and operating system repositories are not configured by {productname}.
- Container image references inside blueprint values are not rewritten. Your {containerd} registry mirrors must resolve them transparently.
- Git over SSH is not supported. Use HTTPS with credentials and, where required, a private CA certificate.
- Upgrade, rollback and retry apply to blueprint workloads only. A workload that has never reached a healthy, fully rolled out state has no rollback target.

== Release 2.1.0

This release builds on the 2.0.x line with an operator-served application catalog that is now the default, git-backed {ranchera} catalog support, expanded {nvidia} integration, hardened extension chart delivery, and a range of workload/UI reliability fixes.

=== What's new

==== Application catalog
- *Operator-served catalog, now the default*: The operator serves the application catalog through a static catalog configuration and a CRD lifecycle job, and the UI now loads applications from this bundled catalog by default (`useStaticCatalog=true`). Runtime discovery from live chart repositories remains available by setting the flag to `false` link:https://github.com/SUSE/aif/pull/145[#145], link:https://github.com/SUSE/aif/pull/172[#172].
- *{nvidia} AI Enterprise library*: The {nvidia} {ailibrary} is populated with {nvidia} AI Enterprise-supported {helm} charts, and the default catalog ships the org-level {nvidia} repositories out of the box link:https://github.com/SUSE/aif/pull/155[#155], link:https://github.com/SUSE/aif/pull/172[#172].
- *Application sorting and support labels*: The `Apps` page sorts supported applications first (default) or by name, shows {nvidia} support status through labels, and defaults the library filter to all libraries. The sort control is shared across the `Apps`, `Blueprints`, and `Workloads` screens link:https://github.com/SUSE/aif/pull/155[#155], link:https://github.com/SUSE/aif/pull/172[#172].
- *NGC team repositories*: The operator supports {nvidia} NGC team repositories with gated authentication. The default catalog currently ships only the org-level {nvidia} repositories, so team-repository provisioning is dormant until the catalog expands link:https://github.com/SUSE/aif/pull/163[#163].

==== Git-backed {ranchera} catalogs and {ranchera} API access
- *Git-backed `ClusterRepo` support*: Blueprint components and application workloads can now be deployed from git-backed {ranchera} `ClusterRepo` resources (`spec.gitRepo`/`spec.gitBranch`), including the built-in `rancher-charts` and `rancher-ui-plugins` repositories, which previously failed. The operator fetches the chart from the {ranchera} catalog API on the management cluster and ships it as an embedded {fleeta} `Bundle`, so air-gapped downstream clusters deploy without each cluster needing to reach {ranchera} or hold an API token. Identical reconciles are skipped through a chart fingerprint link:https://github.com/SUSE/aif/pull/156[#156].
- *{*ranchera*} API access settings*: A new *Settings > Rancher API Access* section manages the {ranchera} catalog credential end to end. Selecting btn:[Authorize] mints a {ranchera} API token as the signed-in user, btn:[Test] validates a token before saving, and the section shows the granted expiry and warns before it lapses. When the token expires, select btn:[Authorize] again to renew it. The {ranchera} CA certificate is discovered automatically when none is configured, so TLS verification stays enabled by default. The configuration is hot-reloaded without an operator restart link:https://github.com/SUSE/aif/pull/156[#156].
- *Oversized git charts fail fast*: Charts whose unpacked {fleeta} `Bundle` would exceed the {kube} object-size limit fail terminally with `ChartTooLarge` and guidance to host them in an OCI or HTTP `ClusterRepo` instead, rather than retrying indefinitely link:https://github.com/SUSE/aif/pull/156[#156].

==== Extension delivery and security
- *Authenticated and TLS registries*: `InstallAIExtension` can pull the UI extension chart from authenticated and TLS-enabled registries. The `aif-operator` {helm} chart exposes the corresponding {helm} authentication and TLS settings for the bundled extension link:https://github.com/SUSE/aif/pull/162[#162].
- *Registry hardening*: A registry-host allowlist guards against confused-deputy requests (with a startup warning when the allowlist is empty), insecure registry TLS is gated behind two explicit opt-ins, plain-HTTP OCI chart pulls are no longer performed, and `https+tls` chart URLs that are not a direct `.tgz` are rejected. Terminal reconcile failures now correctly set `Ready=False` link:https://github.com/SUSE/aif/pull/162[#162].

==== Workload and blueprint management
- *Pre-flight credential checks*: Blueprint credentials are validated before installation, so missing credentials are reported up front instead of surfacing as a failed deployment link:https://github.com/SUSE/aif/pull/148[#148].
- *Clearer failure reporting*: Workload failure reasons are shown on the `AI Workloads` list, and `ClusterRepo` resolution failures are surfaced on the `AIWorkload` status link:https://github.com/SUSE/aif/pull/148[#148].
- *Protected bundled blueprints*: Deletion of bundled blueprints is rejected by the API, and the delete action is hidden for them in the UI link:https://github.com/SUSE/aif/pull/122[#122].
- *Updated blueprint*: The `simple-chatbot-with-rag` blueprint is updated to version 1.0.2. The default model changes from `gemma:2b` to `qwen2.5:3b` (larger context window); `qwen2.5:3b` is provided for research use only under the Qwen Research License link:https://github.com/SUSE/aif/pull/154[#154].

=== Key fixes
- {ranchera} and operator index caches are refreshed when the extension version changes, self-healing a stale index cache after an extension upgrade link:https://github.com/SUSE/aif/pull/152[#152].
- `InstallAIExtension` status is patched to avoid `resourceVersion` conflicts link:https://github.com/SUSE/aif/pull/140[#140].
- The family label is preserved when saving an edited blueprint as a new version link:https://github.com/SUSE/aif/pull/139[#139].
- Pull-secret namespaces are no longer created on the management cluster for downstream-only workloads link:https://github.com/SUSE/aif/pull/130[#130].
- The UI clarifies that the blueprint installation namespace is only a default link:https://github.com/SUSE/aif/pull/141[#141].
- Deployment type cards are aligned to equal height link:https://github.com/SUSE/aif/pull/129[#129].

=== Upgrade notes
- *CRD lifecycle on upgrade*: The operator chart applies and upgrades its custom resource definitions (CRDs) through a pre-upgrade job (`crds.manageWithJob=true`), which only creates or updates CRDs and never deletes them. In restricted environments where the job cannot run, set `crds.manageWithJob=false` and apply the CRDs from the chart's `crds/` directory manually before upgrading link:https://github.com/SUSE/aif/pull/145[#145].
- *Git-backed catalogs require a {ranchera} token*: To deploy from git-backed `ClusterRepo` resources, authorize a {ranchera} API token under *Settings > Rancher API Access* after upgrading. Charts too large to ship as a {fleeta} `Bundle` fail with `ChartTooLarge`; host those in an OCI or HTTP `ClusterRepo` instead link:https://github.com/SUSE/aif/pull/156[#156].

== Release 2.0.0

This is the *first official release* of {productname}, bringing comprehensive AI workload management capabilities to {ranchera}.

{saifactory} is a {ranchera} UI Extension for managing AI workloads and applications across {kube} clusters.
This extension provides a unified interface for installing, managing and monitoring AI applications in {ranchera}-managed clusters.

[NOTE]
====
This extension requires an active link:https://www.suse.com/products/ai/[{suse} AI Factory] subscription to access the application catalog.
====

=== What's new

==== Core features

===== AI workload management
- *Multi-cluster AI workload deployment*: Deploy and manage AI applications across multiple {ranchera}-managed {kube} clusters from a single interface
- *Blueprint-based application templates*: Preconfigured application blueprints for common AI use cases:
* Simple Chatbot with RAG (Retrieval-Augmented Generation)
* Simple Chatbot with RAG using {vllm}
* {nvidia} RAG Minimal deployment
* {suse} Inference Endpoint
- *Declarative workload definition*: Kubernetes-native Custom Resource Definitions (CRDs) for AI workloads, blueprints, and settings
- *GitOps integration*: Fleet-based GitOps workflow support for managing AI workload configurations

===== User interface
- *Unified dashboard*: Overview page with at-a-glance statistics and recent activity
- *Application catalog*: Browse and install AI applications from {suse} AI Factory and {nvidia} {ailibrary}
- *Multi-step installation wizard*: Guided workflows for deploying applications and blueprints
- *Application instance management*: Monitor and manage deployed AI workloads and their metrics
- *Blueprint management*: Create, edit, and manage custom blueprints
- *Settings management*: {helm} and Git repositories configuration

===== Operator and backend
- *{suse} AI operator*: {kube} operator managing the lifecycle of AI extensions and workloads
- *Custom resource definitions*:
* `AIWorkload`: Defines AI application instances
* `Blueprint`: Defines reusable application templates
* `InstallAIExtension`: Manages UI extension installation
* `Settings`: Centralized configuration management
- *Multiple deployment strategies*: {helm} for simple deployments to local clusters, {fleeta} integration for GitOps for downstream and multi-cluster deployments
- *Multi-vendor support*: Seamless integration with both {suse} and {nvidia} AI components
- *Credential management*: Automatic injection of registry credentials and pull secrets

===== Integration and connectivity
- *{suse} application collection integration*: Access to curated AI application catalog
- *{nvidia} NGC integration*: Direct access to {nvidia} AI applications and models
- *{fleeta} integration*: GitOps-based deployment workflows
- *Multi-cluster support*: Deploy to local and downstream {ranchera} clusters

=== Known issues and behaviors

==== Installation and deployment
- {fleeta} must be installed before deploying the AIF operator, the installation of the AIF operator may fail.
- Standalone UI extension installation through {ranchera} Extensions interface is not supported.
Use the AIF operator default values to install it.
- Images are distributed via GitHub Container Registry (ghcr.io).
In the following releases, images will be distributed via the {suseregistry}.

==== {nvidia} blueprints
- **RAG v2.5.1+**: rag-server image version 2.5.1 does not exist in the registry. See link:https://github.com/{nvidia}-AI-Blueprints/rag/issues/618[#618].
- **RAG v2.5.0+**: nv-ingest deployment renders duplicate `OTEL_EXPORTER_OTLP_ENDPOINT` environment variable, causing Fleet/ArgoCD deployments to fail. See link:https://github.com/{nvidia}-AI-Blueprints/rag/issues/687[#687].
- **RAG v2.6.0**: NIM embedding and reranking charts do not pass `model.profiles` to NIMCache, causing all profiles (~11) to download instead of the selected one. See link:https://github.com/{nvidia}-AI-Blueprints/rag/issues/681[#681].
- **RAG v2.5.1+**: Service names use hardcoded `nvidia-blueprint-rag` prefix and ignore `nameOverride`/`fullnameOverride` values. See link:https://github.com/{nvidia}-AI-Blueprints/rag/issues/662[#662].
- **RAG v2.6.0**: *Critical* - NIMs cannot be deployed in air-gapped environments; chart missing `spec.storage.pvc.name` field to use existing PVC. See link:https://github.com/{nvidia}-AI-Blueprints/rag/issues/693[#693].
- **AIQ v2.1.0**: Chart hardcodes `ns-aiq` namespace, ignoring release namespace; incompatible with Fleet/ArgoCD. See link:https://github.com/{nvidia}-AI-Blueprints/aiq/issues/290[#290].
- **AIQ v2.1.0+**: Local inference configuration requires manual ConfigMap creation; not documented or exposed via {helm} values. See link:https://github.com/{nvidia}-AI-Blueprints/aiq/issues/302[#302].
