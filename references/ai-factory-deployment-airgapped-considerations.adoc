Deploying {productname} in an air-gapped environment requires local artifact registries, a local model cache, and secure TLS endpoints.
These local resources ensure that you can deploy and run AI applications securely without external internet connectivity. 
When planning your deployment, ensure that you consider the following:

* *Application catalog.* By default, the {kube} operator serves a built-in application catalog, so you can browse and install applications without the management cluster reaching out to live chart repositories.
Keep this default in air-gapped environments; only enable runtime catalog discovery if you host the corresponding chart repositories locally.

* *OCI artifact repositories.* In a connected environment, {productname} pulls artifacts from external sources to deploy AI applications.
These artifacts include {helm} charts and container images.
In an air-gapped environment, you must host these artifacts locally because external network access is prohibited.
Mirror or import these artifacts to local OCI-compliant repositories.
Configure the local repositories similarly to the external sources to ensure a seamless transition.

* *Model cache.* AI applications can consume AI models from external sources, such as {huggingface} or {nvidia} NGC.
AI models consist of binary files arranged in specific directory layouts.
To use a model cache, store model data in Persistent Volume Claims (PVCs) attached to the application pods.
For multi-node or multi-cluster deployments, the PVC provisioner must support distributed storage, such as NFS or Longhorn.

* *Endpoint security.* Although you can use self-signed TLS certificates for local OCI-compliant repositories, we recommend using certificates signed by your organization's certificate authority (CA).

* *UI extension chart source.* The UI extension chart can be pulled from an authenticated, TLS-enabled local registry.
Configure the registry credentials and TLS settings through the `aiExtension.source.helm` values of the `aif-operator` chart.
For a private CA, provide the CA certificate rather than skipping verification.
Restrict which registry hosts the operator may pull from by setting an allowlist (`manager.allowedRegistryHosts`); leaving it empty allows all hosts.

* *Blueprint portability.* Blueprints reference a chart repository by its identity rather than by its URL.
The registry endpoints you configure om the `Settings` page determine where that repository is hosted, so the same blueprints deploy unchanged against your local mirror.
Both the {nvidia} application and {nvidia} blueprint repositories are preserved when mirrored, so {nvidia} blueprints continue to resolve.

* *Private CA certificates.* Store the PEM-encoded CA certificate in a secret in the `aif-operator` namespace and select it for {sappco}, {sregistry} and {nvidia} in menu:SUSE AI Factory[Settings].
{productname} propagates the certificate to {ranchera} and {fleeta}, and handles certificate and credential rotation, so you do not need to disable TLS verification.

* *Private Git repositories.* Blueprint input and GitOps output support HTTPS Git repositories with credentials and a private CA certificate.
Git over SSH is not supported.

* *Container images.* Set `global.imageRegistry` on the `aif-operator` chart to redirect every image shipped by the operator and the UI extension to your local registry, and set `global.imagePullSecrets` for the corresponding credentials.
The CRD lifecycle job additionally requires the `kubectl` image defined by the `crds.image` values, so mirror that image as well.

* *Cluster preparation is a separate task.* {productname} configures its own chart repositories, Git access, credentials and CA trust.
It does not configure node and {containerd} registry mirrors, registry fallback policy, DNS, host proxies or operating system repositories.
In particular, container image references inside blueprint values are not rewritten, so your {containerd} registry mirrors must resolve them transparently, as described in xref:ai-factory-deployment-airgapped-workflow-configure-rke2[].
